# 🚀 Helpy: Экосистема горизонтальных сообществ

**Кейс-Чемпионат СПК | Студенческий совет**

Telegram Mini App и веб-панель для создания, управления и масштабирования неформальных сообществ внутри крупных организаций (ВУЗы, банки, IT-компании, госструктуры). Превращает хаос неформальных связей в устойчивую экосистему.

---

## 🎯 Основные возможности

- **Верификация пользователей:** Подтверждение принадлежности к организации через корпоративный домен (с соблюдением 152-ФЗ).
- **Создание сообщества за 3 шага:** Название, описание, теги и тип доступа. Автор автоматически становится администратором.
- **Умный каталог:** Единая лента с фильтрацией, поиском по названию и тегам.
- **Управление и аналитика:** Роли (админ, модератор), публикация анонсов, просмотр статистики вовлеченности.
- **Жизненный цикл:** Автоматическая архивация неактивных сообществ и механизм передачи прав при уходе администратора.
- **Ресурсная поддержка:** Встроенный модуль бронирования помещений и запроса микро-бюджетов на мероприятия.
- **Виральность:** Нативный шеринг в Telegram, реферальные ссылки и QR-коды для органического роста.

---

## 🛠 Технологический стек

- **Frontend:** React, Vite, Telegram WebApp SDK, CSS-переменные Telegram (Mobile First).
- **Backend:** Node.js, Express.
- **Database:** MongoDB (Mongoose).
- **Deploy:** Vercel (Frontend) + Render (Backend) + MongoDB Atlas.

## 👥 Роли и пользовательские сценарии

### 🟢 Новичок (Студент 1 курса / Новый сотрудник)
Хочет быстро найти единомышленников. Проходит верификацию по почте, ищет сообщество по тегу (например, `#спорт`), вступает в 1 клик и получает приглашение на ближайшее мероприятие.

### 🟡 Опытный участник (Старшекурсник / Senior)
Готов делиться опытом, но не любит бюрократию. Создает свое сообщество за 30 секунд через пошаговый мастер, назначает модераторов и делегирует рутину.

### 🟠 Организатор (HR, Педагог, Куратор)
Нуждается в автоматизации. Использует панель управления для одобрения бронирований помещений, запросов бюджета и мониторинга активности лидеров.

### 🔴 Руководитель (Декан, HR-директор)
Заинтересован в метриках. Получает сводную аналитику по вовлеченности и удержанию талантов, не вникая в ручное управление.

## 📁 Структура проекта

```text
hack/
├── backend/                  # Серверная часть (API)
│   ├── config/               # Настройки подключения к БД
│   ├── models/               # Схемы MongoDB (User, Community, Event)
│   ├── routes/               # API эндпоинты (auth, communities, events)
│   ├── middleware/           # Проверка прав доступа и CORS
│   ├── .env                  # Переменные окружения (не коммитить!)
│   └── server.js             # Точка входа
│
└── frontend/                 # Клиентская часть (Telegram Mini App)
    ├── public/               # Статические файлы
    ├── src/
    │   ├── api/              # Настройка axios-клиента
    │   ├── components/       # Переиспользуемые UI-компоненты
    │   ├── pages/            # Экраны: Auth, Catalog, CreateCommunity, CommunityDetail
    │   ├── App.jsx           # Роутинг и инициализация Telegram WebApp SDK
    │   └── main.jsx          # Точка входа React
    └── index.html            # Подключение скрипта Telegram WebApp
```

## ⚙️ Переменные окружения (.env)

Создайте файл `.env` в папке `backend` и заполните его своими данными:

```env
PORT=10000
MONGO_URI=mongodb+srv://<db_username>:<db_password>@cluster0.mongodb.net/helpy?retryWrites=true&w=majority
JWT_SECRET=your_super_secret_jwt_key_change_this
TELEGRAM_BOT_TOKEN=your_telegram_bot_token_from_botfather
FRONTEND_URL=https://helpy-frontend.vercel.app # Ссылка на ваш фронтенд для CORS
```
> ⚠️ **Важно:** Никогда не коммитьте реальные пароли и токены в Git.

## 📦 Установка и локальный запуск

### 1. Запуск Backend
```bash
cd hack/backend
npm install
npm run dev
```
*Сервер будет доступен по адресу: `http://localhost:5000`*

### 2. Запуск Frontend
Откройте **новый терминал**:
```bash
cd hack/frontend
npm install
npm run dev
```
*Приложение будет доступно по адресу: `http://localhost:5173`*

## 🔐 Безопасность и 152-ФЗ

- Сбор персональных данных происходит только после явного согласия пользователя (чекбокс в форме регистрации).
- Верификация осуществляется через проверку корпоративного домена электронной почты, что минимизирует риски попадания посторонних лиц.
- Аутентификация построена на базе JWT-токенов, пароли в открытом виде не передаются и не хранятся.
